SEC-01 · ENTRY LIMITSMedium · Reproduced

A few attempts can block other visitors.

ThreatThe entry allowance follows the server's immediate network connection, which may be shared by visitors. Six new-session requests filled that allowance before any human verification ran.

Selected solutionSeparate a larger service entry guard from each run's small challenge allowance. A blocked run no longer fills another visitor's small bucket. No forwarded-IP trust or visitor tracking.

Keep the ten-document batch, one batch verification, four parallel requests and existing paid ceilings. No new processing dialog.

What the evidence means

The seventh local request returned 429; no challenge or provider call ran. The exact grouping of visitors on Google's live network remains unmeasured. Simply trusting a forwarded IP would introduce a new weakness.

Approved · Local repair implemented; settled review passes.

SEC-02 · UPLOAD APPROVALMedium · Reproduced

Rejected uploads still do expensive work.

ThreatSomeone with one valid upload approval can change request details and make the server inspect PDFs before it rejects the mismatch. Reusing that approval can waste shared capacity.

Selected solutionMatch every approved detail before starting PDF inspection or recording workspace intake. Keep the final single-use paid check immediately before the provider call.

Unsupported files must keep their useful guidance without burning a paid allowance. Preserve cancellation, explicit retry and genuine batch processing.

What the evidence means

Two mismatched local requests were rejected, but both reserved unapproved workspace intake first. No paid call occurred. This is wasted work before rejection, not a bypass that obtains paid processing.

Approved · Local repair implemented; settled review passes.

SEC-03 · PUBLIC TRAFFICMedium · Control gap

Bots can occupy the app before Turnstile.

ThreatPage requests, free configuration/rate lookups and unapproved submissions still use runtime capacity. The public Google URL stays reachable; DNS-only Cloudflare records do not filter this traffic.

Selected solutionAdd cheap application request limits, reject invalid approvals earlier and combine concurrent free lookups. Keep uploads streaming. Stronger edge protection remains an optional infrastructure choice.

Keep normal navigation, anonymous exchange rates, cold starts and four uploads working. No invented rate, user-account requirement or new data store.

The cost and DDoS tradeoff

A USD 5 Cloud Run spend cap is already configured, with possible billing lag. It limits exposure but does not keep the site responsive. App limits reduce work; stronger flood protection needs a protected edge that also closes the Google-URL bypass.

Approved · Application guards selected; no edge rollout.

SEC-04 · PDF MEMORYMedium · Measured

Heavy PDFs may interrupt other requests.

ThreatThe worker's JavaScript heap limit does not cover all decoded image memory. Four demanding PDFs could pressure the shared backend, despite file-size and timeout limits.

Selected solutionTwo native inspections at a time, bounded request-owned waiting and a memory headroom stop. Four uploads and paid operations still overlap; cleanup waits for each worker to stop.

Preserve scans, handwriting, exact results, originals and normal parallel processing. Do not cut concurrency or reject useful PDFs by guesswork.

What is and is not proved

Four small inline-image PDFs reached about 944 MiB RSS before timing out. The repaired isolated candidate stopped that workload around 640 MiB, kept genuine originals working and passed the 20 MiB/20-page envelope. The monitor provides measured headroom; it is not an absolute memory guarantee for every PDF.

Approved · Measured containment implemented locally.
