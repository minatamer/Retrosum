# RET-011 — Retro capabilities and provider parity

Owner request, 9 October 2026: make Retro useful throughout the demo in fake and real API modes, working without an API key. This amendment extends the settled `/demo` redesign. No paid request, key, deployment or external integration is required for this work.

## Interaction contract

**Latest owner amendment, 10 October 2026:** Empty chat has four main examples. During conversation, a single bounded row follows the latest valid reply: relevant highlights/related topics, clarification choices or chart styles. Labels and submitted messages match. Stale replies cannot retain yes/no/style actions. Source evidence is default-closed under Show sources. The Retro header offers a larger view (roughly 64% viewport width, bounded by available content, and 75% usable viewport height); arrow collapse/reopen remembers the selected size. Standing clear-chat and cancel-turn controls are removed; timeout/context cleanup and explicit confirmed clear-chat proposals remain.

OpenAI uses the same validated intent-driven shortcuts. Both adapters explicitly select standard pricing. See [private live test preparation](../engineering/OPENAI-LIVE-TESTING.md) for the offline-first runner and remaining public-live acceptance gates.

**Latest owner amendment, 9 October 2026:** Workspace export is removed. Keep original PDF preview/downloads, clear-chat and Reset confirmation. Retro no longer offers an export shortcut or actionable export proposal in either mode. Legacy saved export messages still decode so removing this option does not discard a workspace. Earlier ZIP/export capability descriptions below are superseded.

Both providers return the same strict, bounded intent schemas. Application code calculates every figure, resolves records and sources, renders editable controls, and executes the visitor's confirmed action. A model response is a proposal, never authority. Fake mode recognizes representative phrases; it does not provide unrestricted language understanding. The actual OpenAI Responses adapter is exercised with injected HTTP responses, including tool continuations. Seventeen actual live intent/grounding cases and two actual-byte document passes passed; real localhost Turnstile/browser checks passed. The configured USD 5 OpenAI spending limit is owner-confirmed; broader/manual/hosted acceptance remains separate.

All actions retain current workspace/revision/scope checks. Layout proposals also bind to their independent layout revision and reject replay. Financial and layout changes retain separate latest Undo. Reset and clearing conversation require explicit confirmation. A model cannot supply URLs, selectors, code or financial calculations.

## Boundaries and later ideas

Document tax is a disclosure, never inferred liability or advice. Cash movement is not a bank balance. Unknown settlement, rates and missing history stay unknown. Real transfers, email, bank linking, web fetching, external accounting writes, persistent chat, scheduled jobs, payroll, inventory, external bank reconciliation, tax filing and investment advice are outside this browser demo. Multi-action batches, arbitrary formulas, external reports and forecasts require separately designed contracts and acceptance checks; they are not claimed as implemented.

## Implementation and verification plan

1. Shared typed workspace intents, bounded optional UI context and document-inventory read tool; exact explanation topics from the existing money catalogue. Packages remain pure.
2. Fake intent routing and live instructions/context share all declared actions. Expose labelled widgets for live target resolution; derive provider topics from the schema.
3. One interactive renderer reuses OriginalViewer, DocumentReview and settings/reset/intake screens. Editable filters and target proposals revalidate at the applying click. Legacy export responses render only explanatory copy.
4. Scenario matrix through fake classification and the actual OpenAI adapter with injected Responses envelopes; negative, stale, schema and zero-network cases. Existing money/CRUD/chart tests remain authoritative.
5. CUA browser checks at desktop and narrow-phone widths, then settled root gates. Record fake browser, injected-provider, actual local live and pending manual/hosted evidence separately.

OpenAI integration follows the official [function calling guide](https://developers.openai.com/api/docs/guides/function-calling) and [Structured Outputs guide](https://developers.openai.com/api/docs/guides/structured-outputs): strict objects, required declared fields (nullable where needed), allow-listed tools, bounded stateless requests and validated application execution. No executable chart configuration or provider arithmetic.
