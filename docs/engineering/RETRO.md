# Retro conversation and guidance (RET-007)

Retro is always present as a forest glass pill with an expandable floating conversation. User text is bubbled; assistant text is unboxed. The shortcut row scrolls horizontally, limiting the dock height on narrow screens. Exact figures, readable period/as-of labels, source chips, collapse/expand and latest Undo remain native controls. There is no animation-off setting or circular launcher.

## One financial authority

`packages/contracts` owns bounded prompt/snapshot, tool, target, scope and response schemas. A finalized message can store the typed response alongside inert introductory text. Existing projections without that optional field still restore. Only complete user/answer pairs persist; pending stages, controllers, highlights and tours never restart after refresh. The existing 40-message/two-hour browser projection bounds apply.

`packages/money` owns generic fake intent selection, topic-to-fact mapping, grounding, source verification, vetted explanation templates and bounded read-tool queries. All amounts come from the RET-006 catalogue. No provider totals or free prose become financial authority. Live language is intentionally constrained to selecting topics, exact fact IDs, clarification/limited-result reasons and registered targets. This avoids pretending a digits-only prose filter can establish semantic grounding. Model-written causes, recommendations and unsupported paid/open claims cannot enter the approved explanation vocabulary.

Responses bind workspace identity, revision and full period/as-of/category/counterparty scope. Stale stored answers hide their former financial claims and source actions, while an explicit local refresh uses current facts. Selected contributor details also read the current catalogue. A late turn is checked against both revision/generation and filter scope after investigation and immediately before completion. Unverifiable stored response sources are rejected, rather than rendered as citations.

## Simulation, local guidance and live boundary

One backend capability contract controls mode. Local tour/summary/explanation/source actions require no model requests and remain available when capability reading or live AI fails. Reconnect Retro rereads configuration deliberately; it does not send a paid turn. Fake typed messages simulate understanding/staging/validation and use the same grounding contract against actual current records, with zero chat/provider network dispatch. They handle summaries, rent, cash versus work, supplied comparisons, largest contributions, coverage, clarification, refusal, unsupported history/advice/injection, deliberate failure/tool-cap examples and a delayed `simulate stale summary` scenario. They do not claim general natural-language CRUD before RET-008.

The backend has a `RecordInvestigator` port and a bounded loop: at most three model requests, four aggregate tools, a whole-turn 60-second abort race and no automatic retries or repair. It parses and validates the submitted graph and recomputes the catalogue. Tool queries cap event/contact/issue lists at 20, metric contributors/references at 50 with pagination, source excerpts at 2,000 characters and exact locators. Contact email/account extension fields stay outside model context. Tool/schema/unknown-ID rejection grants no executable authority.

The same-origin Next bridge forwards only `/v1/chat`, with exact-origin checks, actual request-byte/output-byte caps, abort propagation, safe errors and no-store responses. Backend origin/capability checks precede JSON parsing. A shared instance-capacity guard prevents chat/extraction overlap; content-free process-local turn counters allow eight attempts per stable run identity and reject replay. They are not a durable person/account quota. Action grants, challenge verification and monetary reservations remain RET-010’s live-release prerequisite; consequently public live chat stays closed even with inherited keys/flags.

The OpenAI Responses adapter uses strict declared function tools and a structured decision envelope, `store: false`, foreground mode, low reasoning and 1,500 output tokens. Opaque reasoning/function continuation stays in a weak per-turn adapter context, never in final answers or browser persistence. Its input representation is bounded and conservatively checked; an evaluated token/cost envelope is still required before live release. Mocked transport verifies native continuation and refusals/incomplete/invalid responses; no real OpenAI request was made. References rechecked 8 October 2026: [function calling](https://developers.openai.com/api/docs/guides/function-calling), [structured outputs](https://developers.openai.com/api/docs/guides/structured-outputs).

## Application-owned motion

`targets.ts` is the finite registry of stable IDs, owning workspace views and tour copy. Lookup resolves only a currently mounted, visible registered element. Navigation never accepts a remote URL or provider CSS selector. The eight local steps cover overview, scope, income, composition, cash, originals, Records and Retro. Scope guidance opens its real disclosure. Highlight rectangles render in a body portal so the transformed dock cannot offset their viewport coordinates.

Back/Next/Finish work without focusing a target or interrupting typing. Manual navigation/history, wheel/touch scrolling, relevant keys, resize/visual-viewport changes, dialog opening, target removal, scope/revision change and generation/reset invalidate guidance. Single highlights expire automatically. Tours temporarily hide chat history and entry shortcuts to keep the pointed dashboard visible; accepting a contextual Yes/show action collapses the conversation. No/thanks dismisses that response’s suggestion locally. Source dialogs use the existing top layer and focus return.

The shell measures dock height plus 40 px into an owned CSS variable and tracks visual-viewport height/keyboard offset. Geometry updates use owned style properties rather than rerendering the entire workspace. This is local browser evidence; actual mobile keyboard and physical touch/zoom acceptance remain owner checks.
